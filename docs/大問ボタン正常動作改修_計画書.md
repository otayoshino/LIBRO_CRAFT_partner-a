# 大問ボタン正常動作改修 計画書

作成日: 2026-07-17
参考実データ: `sample_books/8a24127cb94d4a158ae43954184af569/p0004.json`（大問ボタン3組を含むページ）

## 現状調査結果（実機Playwright検証済み）

改修に先立ち現状を実機検証した。**CRAFT編集画面側の基本機能は既に実装済みで動作している**。壊れている・欠けているのは「押下状態の見た目」と「LIBRO book書き出し」の2点である。

### 動作している機能（リグレッションさせないこと）

1. 付箋を複数選択（Shift+クリック）すると「付箋パーツ操作」ペインの「大問ボタン」が活性化される（`updateStickyOpsPanel`、[app/js/annotation-interaction.js](../app/js/annotation-interaction.js) 1592行付近）。新規付箋・LIBRO由来付箋（`.libro-toggle`）のどちらでも動作確認済み
2. 活性化中に押下すると大問ボタンが作成され、選択中の付箋に `dataset.daimonId` で紐付く（`createDaimonButton`、[app/js/buttons.js](../app/js/buttons.js) 159行付近）
3. 閲覧モードで大問ボタンをクリックすると、紐付いた付箋の表示/非表示が一括トグルされる（`addDaimonClickHandler`、buttons.js 222行付近）
4. 大問ボタンが押下状態（付箋一括非表示）のとき、非表示付箋（`state-hidden`＝`opacity:0`、要素は残る）の位置を個別クリックするとその付箋だけ表示に戻り、大問ボタンの状態は変わらない（付箋側クリックハンドラが独立しているため現状の構造で自然に成立）

### 不具合1: 押下状態の見た目が変わらない（CRAFT閲覧モード）

大問ボタンは押下状態（＝紐付き付箋がすべて非表示の状態）のとき**グレーのソリッドカラー**になるべきだが、現在は見た目が一切変わらない。

- 原因: `swapButtonPressedImage`（buttons.js 112行付近）は `btn.dataset.btnHasImage === '1'`（カスタム画像設定済み）の場合しか動作しない。プリセットモード（背景色＋「大問」ラベル、新規作成時のデフォルト）のボタンには押下時見た目が未実装
- LIBRO由来の大問ボタン（元画像＋押下画像がbook内に存在）は `has-custom-image` になるため正しく切り替わる

### 不具合2: LIBRO book書き出しで新規大問ボタンが消える・画像が出力されない

- `saveAnnotationsAsLibroBook`（[app/js/storage.js](../app/js/storage.js) 460行付近）の `supportedTypes` に `daimon` が含まれず、新規作成した大問ボタンは「未対応種別」として警告のうえ**丸ごと捨てられる**（「画像が正しく出力されない」の実体は、そもそもアノテーション自体が書き出されていない）
- LIBRO由来かつ未編集の大問ボタンのみ、読込時生データのpassthroughで書き戻される（既存実装、維持すること）

## LIBRO実データにおける大問ボタンの構造（p0004.jsonで確認済み）

大問ボタンは付箋と同じ **Hide/Showトグルペア（2 annot）** で、targetsに紐付き付箋のIDを配列で持つ。p0004.json の実例（ID 920/921 のペア、紐付き付箋は 900〜919 の10ペア）:

```json
{ "filename": "annots/0920.png", "rect": [309,666,194,116], "hidden": true,
  "actions": [
    { "action": "Hide", "targets": [900,902,904,906,908,910,912,914,916,918,920] },
    { "action": "Show", "targets": [901,903,905,907,909,911,913,915,917,919,921] },
    { "action": "Hide", "targets": [920] },
    { "action": "Show", "targets": [921] } ] },
{ "filename": "annots/0921.png", "rect": [309,666,194,116],
  "actions": [
    { "action": "Hide", "targets": [901,903,905,907,909,911,913,915,917,919,921] },
    { "action": "Show", "targets": [900,902,904,906,908,910,912,914,916,918,920] },
    { "action": "Hide", "targets": [921] },
    { "action": "Show", "targets": [920] } ] }
```

読み解き（付箋ペアは「開＝小ID・初期hidden / 閉＝大ID・初期表示」の規則。SKILL.md参照）:

- **921 = 通常時ボタン**（初期表示、`hidden`なし・ペアの大ID側）。画像は `annots/0921.png`（通常デザイン）。クリックすると: 全付箋の「閉」(901,903,…)をHide＋「開」(900,902,…)をShow（＝付箋を一括非表示にして解答を見せる）、あわせて自身(921)をHideし押下側(920)をShow
- **920 = 押下状態ボタン**（初期非表示、`hidden: true`・ペアの小ID側）。画像は `annots/0920.png`（**グレーのソリッドカラー、実測色 #666666、余白は透明**）。クリックすると逆の操作（付箋を一括再表示し、通常時ボタンに戻る）
- targetsの並びは「紐付き付箋のID列 ＋ 自身のID」を含む先頭2アクションと、自身ペアだけのHide/Show 2アクションの計4アクション構成（実データ準拠でこの形式に合わせる）
- 大問ボタンが押下状態のとき、個別付箋の「開」画像（その位置に表示されている透明系annot）をクリックすればその付箋だけ閉に戻る。各付箋のペアは自身のみをtargetsに持つため、大問ボタンの状態には影響しない（要望の※の挙動はデータ構造上自然に成立する）

## 実装方針

### A. CRAFT閲覧モード: プリセットモード大問ボタンの押下状態見た目

- 押下状態（紐付き付箋を一括非表示にした直後）: 背景をグレーのソリッドカラー `#666666` に、ラベル文字はそのまま（視認性が悪ければ白のまま）変更する
- 再度押下（付箋一括再表示）: 元のプリセット背景色に戻す
- カスタム画像モード（`btnHasImage === '1'`）の既存動作（押下画像スワップ）は変更しない
- `resetAllButtonPressedImages`（編集モード復帰時のリセット、mode.jsから呼ばれる）でプリセットモードのグレー状態も元に戻るようにする
- 実装位置: `swapButtonPressedImage` をプリセットモード対応に拡張するのが自然（呼び出し元は `addDaimonClickHandler` 内の既存呼び出しのまま）

### B. LIBRO book書き出し: 新規大問ボタンのHide/Showペア変換

#### B-1. 収集（storage.js `saveAnnotationsAsLibroBook`）

- 新規大問ボタン（`type === 'daimon'` かつ `dataset.libroToggle !== '1'`）を未対応種別扱いから外し、専用の収集構造（例: `domDaimonButtons`）として `buildLibroBookExport` に渡す
- 各大問ボタンについて `dataset.daimonId` で紐付く付箋（`.sticky-note[data-daimon-id="..."]`）を特定する。紐付き先は次の2種が混在しうる:
  - 新規付箋（書き出し時に `convertStickyGroupToLibroAnnots` で開/閉ペアが新規生成される）
  - LIBRO由来付箋（`.libro-toggle`、既存の閉/開IDを持つpassthrough）
- 証明ボタン（shomei）紐付きの大問ボタンは、証明ボタン自体が書き出し未対応のため今回は対象外とし、従来同様に警告を出してスキップする（付箋のみ紐付いた大問ボタンを対象とする）

#### B-2. 変換（libro-format.js）

- 大問ボタン1個につき、上記実データ構造どおりの2 annot（押下＝hidden・小ID側が先、通常＝大ID側が後）を生成する。付箋ペアのユニット化（`buildLibroBookExport` 内のID正規化パス、「開が先＝小ID、閉が後＝大ID」の隣接ペア規則）と同じ仕組みに乗せること
- targets には紐付き付箋の開ID列・閉ID列＋自身ペアIDを、実データの4アクション形式で設定する。紐付き付箋のIDは変換段階の暫定IDでよいが、**ページ単位のID正規化パス（既存実装）で連番へ再採番される際に、大問ボタンのtargetsも既存のtargets書換えロジックで正しく追従することを必ず確認する**（追従しない場合はそのロジックを拡張する）
- `libro-craft-meta`（`CRAFT_META_KEY`、`CRAFT_META_TOGGLE_TYPES` には `daimon` が定義済み）に `type:'daimon'` と `role`（pressed/normal相当）・`group-id` を埋め込み、再インポート時に確実に大問ボタンとして復元できるようにする。なお既存インポート（`convertPageAnnotations`）はHide/Show構造の件数一致チェックで大問ボタンを検出するロジックを持つため、構造準拠であればmeta無しでも検出される見込みだが、metaがあればより確実になる

#### B-3. PNG生成（libro-format.js）

- **通常時PNG**: 大問ボタンのCRAFT上の見た目どおりに生成する
  - プリセットモード: プリセット背景色（`BTN_COLOR_OPTIONS[btnPreset]`）＋中央に白文字ラベル「大問」の矩形。CSSの実寸（rect）でラスタライズ
  - カスタム画像モード（`btnImageFile` あり）: `mediaBlobs` の画像バイトをそのまま使用（既存の画像アイコン型書き出しと同じ方式）
- **押下時PNG**: グレーのソリッドカラー `#666666`（不透明、rect全面）で生成する。実データ（annots/0920.png）は角がわずかに透明の角丸だが、ソリッド矩形で十分とする
- 既存の `rasterizeStickyClosedPng` / `rasterizeMarkerPng` と同様のcanvasラスタライズ方式で実装する

#### B-4. 書き出し対象ページの `annot-range` / `index.json` ミラー

既存実装（付箋書き出しと同じパイプライン）に乗るため個別対応は不要のはずだが、大問ボタン追加によりページのannot件数が増えることを踏まえ、既存の半開区間ルール（`[先頭ID, 先頭ID+件数]`）が維持されることをテストで確認する。

## 変更しない箇所（誤って触らないこと）

- LIBRO由来・未編集の大問ボタンのpassthrough書き出し（`daimonPassthrough`、storage.jsの`survivingDaimonIds`）。位置編集が反映されない既知の制約も今回は扱わない
- 答（kotae）・証明（shomei）ボタンの書き出し（未対応のまま）
- 付箋グループ・単独付箋の書き出しロジック（`convertStickyGroupToLibroAnnots`）本体。大問ボタンのtargetsが参照するIDの受け渡しのために必要な最小限の変更（戻り値にID情報を追加する等）は可
- CRAFT編集画面の選択・活性化・紐付け作成のロジック（現状動作している）

## テスト観点

1. **CRAFT押下見た目**: プリセットモードの大問ボタンを閲覧モードで押下→背景がグレー（#666666）になり紐付き付箋が全非表示、再押下→元の色に戻り付箋が全表示。編集モードに戻る→グレー状態がリセットされる
2. **個別付箋の独立動作**: 大問ボタン押下状態（グレー）のまま、非表示付箋の位置をクリック→その付箋だけ表示に戻り、大問ボタンはグレーのまま
3. **書き出し（新規付箋紐付き）**: 新規付箋2件＋大問ボタンを作成→LIBRO book書き出し→p####.jsonに実データ構造どおりの4アクション形式Hide/Showペアが出力され、targetsが付箋ペアのIDと整合していること。annots/に通常時PNG（プリセット見た目）と押下時PNG（グレーソリッド）が出力されていること（PNGのピクセル検証を行う）
4. **書き出し（LIBRO由来付箋紐付き）**: sample_books の p0004 相当ページでLIBRO由来付箋2件に新規大問ボタンを紐付けて書き出し→targetsがLIBRO由来付箋の閉/開ID（正規化後）を正しく参照していること
5. **往復**: 書き出したbookを再インポート→大問ボタンが `.daimon-btn` として復元され、紐付き付箋との連動（閲覧モードのトグル・押下グレー表示）が機能すること
6. **ID正規化整合**: 書き出し後の各ページで annot が連番・穴なし・`annot-range` 半開区間ルールを満たすこと。既存アノテーション（音声・ページリンク等）との混在ページでも壊れないこと
7. **リグレッション**: LIBRO由来・未編集の大問ボタンがpassthroughで従来どおり書き出されること。付箋のみ（大問なし）の書き出しが従来どおりであること
8. **対象外の確認**: 証明ボタン紐付きの大問ボタンを書き出した場合に、従来どおり警告のうえスキップされること（クラッシュしないこと）
