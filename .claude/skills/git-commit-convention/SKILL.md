# コミットメッセージ規約

`git log` の履歴（直近60件）から抽出した実際の運用ルール。

## プレフィックス

`<prefix>: <日本語の説明>` の形式。コロンの後に半角スペースを1つ入れる。

| prefix | 用途 | 使用頻度 |
| --- | --- | --- |
| `feat:` | 新機能の追加 | 多 |
| `fix:` | 不具合修正 | 多 |
| `refactor:` | 挙動を変えないコード整理 | 少 |
| `chore:` | 上記に当てはまらない雑務（設定変更・ファイル整理等） | 少 |

- 該当するprefixがない変更（例：ドキュメント追加、初回コミット）はprefixなしの日本語タイトルでもよい（例：「ファーストコミット」）。迷った場合は `feat:` / `fix:` / `refactor:` / `chore:` のいずれかを優先する。

## 本文

- タイトルは日本語で簡潔に（「〜を実装」「〜を修正」「〜に対応」などで終える体言止め寄りの文体）。
- 具体的な対象（ボタン名・機能名・ファイル名など）を含め、何をしたか一目で分かるようにする。
  - 良い例：`fix: ページリンクのページ移動機能を実装、紙面カラーを透明に変更`
  - 悪い例：`fix: バグ修正`
- 複数の変更をまとめる場合は読点（、）で区切って1行に収める。長くなる場合は本文（タイトル下の空行以降）に箇条書きで補足する。

## ブランチ運用・PR

現時点では `main` ブランチへの直接コミットのみで運用しており、ブランチ運用ルール・PRテンプレートは未確定。今後方針が決まり次第このSkillに追記する。
