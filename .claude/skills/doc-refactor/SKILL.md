# ドキュメントリファクタリング

CLAUDE.md・docs/・`.claude/skills/` 配下のドキュメントとコードの実態が乖離していないか点検し、整理する作業の進め方。

## 点検の進め方

1. CLAUDE.md と docs/ 配下の各ファイルを読み、コード上の事実（ファイル構成・関数名・実装状況）と照合する。
2. ドキュメントが参照する関数名・ファイルパス・状態変数を `grep` 等で実コードから確認する。存在しない／移動している場合は乖離とみなす。
3. Markdownリンクやプレーンテキストでのファイル名言及など、ドキュメント間の相互参照も対象に含める。ファイルを移動・削除する場合は参照元が壊れていないか確認する。
4. 見つかった乖離は下記の規約に従って「更新」「アーカイブ」「新規作成」のいずれかで解消する。

## 更新・アーカイブ・新規作成の判断規約

- **既存ファイルの更新（デフォルト）**：ドキュメントの主題は現役だが記述内容が古い場合（例：ファイルパスが変わった、実装状況が進んだ、設計が確定した）。
- **アーカイブ（`docs/archive/` への移動）**：ドキュメントが特定時点の計画書・実装指示書であり、その計画が完了して別の現役ドキュメントに実質置き換わっている場合。`git mv` で移動して履歴を保持し、中身は改変しない（過去の記録として読めることに価値がある）。削除はしない。
- **新規ファイル作成**：既存のどのファイルにも属さない新しい観点の情報を追加する場合のみ。プロジェクトの全体方針（新規ファイル作成より既存ファイルの編集を優先し、新規作成が必要な場合は必ずユーザーの承認を得る）に従い、作成前にユーザーに確認する。
- **時系列ログ（開発ログ等）は対象外**：日付ごとの作業記録は内容が古くなること自体が本来の性質であり、乖離とはみなさない。タイトルと内容が食い違っている等の指摘があった場合を除き触らない。

## CLAUDE.md と SKILL.md の役割分担

- CLAUDE.md はプロジェクト全体を俯瞰する最小限の情報に留める（コスト面の理由）。ファイルパス・主要関数名など「調べればすぐ分かる事実」は簡潔に書き、詳細な手順・チェックリスト・制約事項は SKILL 側に書いて CLAUDE.md からリンクする。
- 各 SKILL は自分の担当領域（UI変更・LIBRO連携・新規アノテーション種別追加など）のみを扱う。複数 SKILL にまたがる重複記述は避け、一次情報を持つ SKILL へのリンクで済ませる。

## 一括修正時の注意

- 修正対象が複数ファイルにまたがりやすいので、着手前に対象ファイル一覧（乖離箇所と修正方針）を洗い出してから直す。
- アーカイブや削除など元に戻しにくい操作は、着手前にユーザーに確認する。
